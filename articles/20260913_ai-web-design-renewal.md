# AIにWebデザインを作ってもらうとき、最初に渡すべき情報

画像生成AIにWebデザインを頼むとき、どこまで条件を書けばよいか迷いませんか。今回は自分のポートフォリオをデザインからフルリニューアルした手順を使って、渡した情報と、その情報で何を決めたかったかを紹介します。

今回は、ChatGPT Images 2.5で新しいデザインを作り、既存サイトの内容をMarkdownに整理して渡し、そのデザインをAstroサイトへ実装しています。

記事の中心は、目的と掲載内容の整理、デザイン3案の比較、配色の変更、原稿を反映した最終案の作成です。最後に、PC用デザインを実装へ渡した結果も載せます。

以下の長いデザインプロンプト2件は、実際の依頼を記事用に省略・要約したものです。短い指示は原文を掲載しています。後半のテンプレートは、今回の経験をもとに読者向けに作成したもので、実行した原文とは別です。

## 最初に渡す情報と、それぞれの役割

AIにWebデザインを依頼するときは、色や雰囲気以外の情報も先に整理します。次の項目があると、デザイン案の比較と修正がしやすくなります。

| 渡す情報 | 今回の指定 | 案を見るときの確認点 |
| --- | --- | --- |
| 目的・相手 | 制作会社・広告代理店・個人事業主へのスポット開発支援 | 誰に何を頼めるサイトか伝わるか |
| 掲載内容 | サービス、実績、自己紹介、稼働条件 | 必要な情報を省略していないか |
| 導線 | 仕事の相談、制作・開発実績 | 見出しからボタンへ迷わず進めるか |
| 見た目の方向 | 配色・文字・余白の異なる3案 | 色以外の違いも比較できるか |
| 制約 | 架空の実績数・顧客ロゴを追加しない | 元の情報にない内容が混ざっていないか |

この表の確認点は、今回の依頼を振り返って整理したものです。最初に概要を渡し、案を選んだ後に公開中の文章をMarkdownへまとめ直しました。すべての原稿を最初から確定させていたわけではありません。

今回も、架空の顧客ロゴや実績数、受賞歴などは追加しないように指定しました。

## 1. まずはデザイン案を3案作る

最初から実装を依頼せず、実装コードを変更しないように伝えたうえで、デザイン案を3案作ってもらいました。

```text
個人ポートフォリオサイト「meg+gumi」のトップページをリデザインしてください。

まずは実装コードを変更せず、デザイン案の画像を3案作ってください。
各案はデスクトップ幅のWebサイト全体像が分かる縦長のモックアップ画像にしてください。

サイトの目的：
制作会社・広告代理店・個人事業主に向けて、スポットでWeb制作・開発を支援する個人開発者のポートフォリオです。
「相談しやすさ」と「フロントエンドからバックエンドまで任せられる信頼感」を伝えたいです。

掲載したい内容：
- ブランド名：meg+gumi
- メインコピー：必要なところに入り、Web開発を前へ。
- CTA：「仕事を相談する」「制作・開発実績を見る」
- ナビゲーション：HOME / SERVICES / ABOUT / WORKS / WORK STYLE / CONTACT
- サービス：フロントエンド実装、バックエンド開発、Web制作・開発支援
- 実績：EXIF Copy Tool、わりまる / わけたべ、React電卓入力フォーム、DHU ビジョンブック
- 自己紹介・対応スタイル・問い合わせフォーム・SNSリンク

以下の3案を、明確に異なる方向性で作成してください。

A. 白×深緑×ライム
余白を大きく取った、編集デザインのように落ち着いた案。

B. 白黒×青
大きく力強い文字と整ったグリッドを使った、シャープな案。

C. 淡いラベンダー×コーラル×イエロー
親しみやすさを出しつつ、子どもっぽくしない案。

共通の要件：
- 日本語テキストは読みやすく、ダミーテキストを使わない
- 架空の顧客ロゴ、実績数、売上、受賞歴、レビューは追加しない
- スマートフォン表示も意識した余白・情報設計にする
- 実績は画像サムネイルを大きく見せる
```

サイトの目的や掲載内容まで渡すことで、見た目だけでなく、ポートフォリオとして必要な情報を含めた案を比較できます。

## 2. 選んだ案のレイアウトと色を分けて指示する

```text
添付した「白黒×青」のB案をベースに、デスクトップ幅の縦長Webサイトモックアップを1案作成してください。

レイアウト、情報の順序、力強い日本語タイポグラフィ、細い罫線、明快なグリッド、実績カードの配置はB案のまま維持してください。

配色は、既存のmeg+gumiサイトの雰囲気を引き継いでください。
- 背景：白から淡いスレートグレー
- 文字：濃いスレート #0F172A
- 罫線・補助文字：スレートグレー #64748B
- CTAなどの主アクセント：くすませたピンク #EC4899
- 小さなアクセント：アンバー #F59E0B
- 青は使わない
- ピンクとアンバーは面積を小さくする

必ず含める内容：
- メインコピー：「必要なところに入り、Web開発を前へ。」
- CTA：「仕事を相談する」「制作・開発実績を見る」
- ABOUT、WORK STYLE、CONTACT、フッター
```

この依頼では、維持したいレイアウトを先に書き、変更する配色を後に並べました。ピンクやアンバーは色コードだけでなく、使う場所と面積も指定しています。結果が指示どおりかは、出てきた画像で確認します。

![meg+gumiの色変更後のデザイン案](/images/20260913_astra-site-renewal/design-color-adjusted.png)

## 3. 既存サイトの内容をMarkdownで渡す

配色の方向が決まったら、デザインに入れる文章を整えました。今回の題材は公開中のサイトなので、既存の文言を出発点にしています。

そこで、公開中のサイトにある文章をMarkdownに整理しました。Markdownは、見出しや箇条書きで文章の構造を表せるテキスト形式です。

```text
今のWEBサイトの内容をすべて画像生成に入れたいから文字列をすべてmdにして
```

その後、文章量が多く説明的に見えたため、サービス・自己紹介・対応スタイルの文章を短くしました。平日夜・休日中心という稼働条件は残しています。

整えたMarkdownを添付して、画像生成には次のように伝えました。

```text
この内容を変更せず、先ほどのデザイン方向で作成
```

添付したのは、掲載内容を整理した `homepage-content-for-design.md` です。短い指示でも「この内容」が何を指すか分かるように、原稿と一緒に渡しています。

「文章を変えないで」と伝えても、生成結果が原稿と一致する保証にはなりません。実装時の文言は原稿と照合する必要があります。

## 4. デザインを実装へ渡す

デザインと掲載内容がそろったので、lunaで実装を始めました。

```text
デザイン変更を適用させよう
```

ただ、メインビジュアルは思うように形にならず、やり取りが続きました。そこでAstraに切り替え、次のように指示しました。

```text
デザイン再現しつつフルリニューアルやり直してください
```

この短い指示の前に、デザイン画像と掲載内容についてやり取りしています。新しいチャットで同じ一文だけを送っても、実装する対象は伝わりません。自分で試すときも、選んだデザイン画像と確定した原稿を渡し、どのページを作り直すのかを明示する必要があります。

## 5. PC用デザインからレスポンシブ対応する

用意していたデザイン画像はPCサイズだけで、スマートフォン用は作っていません。

それでもAstraは、スマートフォンでは要素を縦に組み替え、サービスや実績カード、問い合わせフォームまで確認できる表示にしてくれました。

![meg+gumiの公開サイトのスマートフォン版全体キャプチャ](/images/20260913_astra-site-renewal/site-final-mobile.png)

確認できたのは、PC用画像だけを渡した今回の実装で、スマホ向けの配置もできていたことです。「一度で」はAstraへ切り替えた後のメインビジュアルとスマホ対応を指します。案の選択や後のナビゲーション調整、公開前の確認は含みません。モデル間の比較条件を揃えた検証ではなく、一つの制作事例として紹介しています。

## 自分のサイトで試すときの記入用テンプレート

次は、今回の依頼で使った項目を整理したテンプレートです。角括弧の部分を自分のサイトに合わせて埋めてください。実際の依頼文そのものではありません。

```text
[サイト名]のWebデザイン案を3案作ってください。
まずは画像で比較したいので、実装コードは変更しないでください。

目的と相手：
- 誰に：[想定する閲覧者]
- 何を伝えるか：[提供するサービスや価値]
- 次にしてほしいこと：[相談・購入・実績の閲覧など]

掲載内容：
[見出し、説明文、サービス、実績、連絡先などを記載または添付]

比較したい方向性：
A. [配色、文字、余白、写真・図形の使い方]
B. [Aとは異なる方向性]
C. [A・Bとは異なる方向性]

共通の条件：
- [必要なセクションとボタン]
- [残したいブランドカラーなど]
- 架空の実績数、顧客ロゴ、受賞歴は追加しない
- PC幅のページ全体が分かる縦長画像にする
- スマートフォンで読むことも意識する
```

案を選んだ後は、採用した画像を添付し、「残す要素」と「変える要素」を分けて伝えます。原稿が固まったら、デザインの調整と文章の変更を同時に頼まず、確定原稿を添付して反映を依頼する形が、今回の進め方でした。

## デザイン画像から、実際に使うページへ

今回共有したいのは、目的と掲載内容を渡し、複数案から選び、残す要素を決めながらデザインを仕上げる手順です。使った指示が同じでも、生成結果が同じになるとは限りません。

デザイン画像で方向を選び、実装後はPCとスマホの表示を見比べる。これから試すなら、画像の見た目に加えて、実際の文章・ボタン・フォームを確かめるところまで含めて進めてみてください。
